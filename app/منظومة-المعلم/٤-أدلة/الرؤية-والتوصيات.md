# منظومة المعلم — التحول إلى منصّة متعددة المدارس: الرؤية والتوصيات

## القرارات المعمارية (موصى بها ومعتمدة)
1. **قاعدة جديدة متعددة المستأجرين (Multi-Tenant):** كل مدرسة = مستأجر مستقل (school_id) — تعزل بيانات كل مدرسة تمامًا.
2. **مصادقة حقيقية (Supabase Auth):** تسجيل دخول بالبريد وكلمة المرور (بدل القفل المحلي). كل مستخدم له هوية آمنة.
3. **أدوار:** super_admin (أنت) / school_manager (مدير المدرسة) / teacher (معلّم) / assistant (مساعد/وكيل) / guardian (ولي أمر).
4. **حفظ فوري لكل عملية (لا مزامنة):** كل تعديل يُكتب مباشرة في قاعدة البيانات لكل الحسابات — لا تجميع ولا رفع لاحق.
5. **أمان صفّي (RLS) على كل جدول:** المعلّم يرى/يعدّل بياناته فقط، المدير يرى كل مدرسته، ولا أحد يرى مدرسة غيره — يُفرض في قاعدة البيانات نفسها (لا في التطبيق فقط).
6. **مرونة بلا فقد بيانات:** كل جدول فيه عمود `data jsonb` — نضيف أي حقل مستقبلًا دون ترحيل أو فقد.

## نموذج الأمان السيبراني
- **العزل:** RLS يمنع أي تسريب بين المدارس على مستوى قاعدة البيانات.
- **أقل صلاحية:** anon لا يصل للجداول مباشرة؛ كل شيء عبر مستخدم مُصادق أو دوال محدّدة.
- **بوابة ولي الأمر:** تبقى معزولة عبر دوال RPC آمنة (لا وصول مباشر للجداول).
- **النسخ الاحتياطي:** خطة Pro تعطي نسخًا يومية تلقائية (حماية من الفقد).
- **التدقيق:** يُنصح بجدول audit_log لتتبّع من فعل ماذا ومتى.
- **الأسرار:** لا تُخزَّن مفاتيح service_role في التطبيق إطلاقًا — فقط anon/publishable.

## هل تحتاج اشتراكًا مدفوعًا في قاعدة البيانات؟
نعم — للإنتاج متعدد المدارس **يُوصى بخطة Supabase Pro ($25/شهر لكل مؤسسة)** للأسباب:
- **الخطة المجانية تُوقِف المشروع بعد ٧ أيام خمول** → غير مقبول لنظام مدرسي حيّ.
- **الخطة المجانية بلا نسخ احتياطي** → خطر فقد البيانات (بياناتك حساسة).
- الخطة المجانية: مشروعان فقط، ٥٠٠ ميغابايت، ٥٠ ألف مستخدم شهريًا.
- **Pro:** يعمل دائمًا (بلا إيقاف) + نسخ يومية + موارد أعلى.

**التدرّج المقترح:** ابدأ التطوير والتجربة على **المجاني**، وعند إطلاق أول مدرسة حقيقية بمستخدمين انتقل إلى **Pro**. بياناتك لا تُفقد عند الترقية (نفس المشروع).

## نموذج الاشتراكات (لتحصيل الرسوم مستقبلًا)
- جدول `subscriptions` جاهز (على مستوى المدرسة والمعلّم): free / basic / pro / school.
- التحصيل في السعودية: بوابات مثل **Moyasar / Tap / HyperPay** (تدعم مدى وApple Pay)، أو Stripe.
- تخزّن حالة الاشتراك (active/expired) وتتحكم بالوصول للميزات حسبها.

## هل تحتاج ترقية اشتراك Claude لتفادي «Resets»؟
- **«Reset» بيئة العمل عندي (الحاوية) لا علاقة له باشتراكك** — هي خاصية تقنية للصندوق، تُصفَّر بين الجلسات بغضّ النظر عن الخطة.
- **الأهم:** مشروعك **لا يعيش في حاويتي** — بل في: (١) الملفات المُسلّمة لك، (٢) موقعك المنشور، (٣) قاعدة Supabase. لذا الـReset **لا يفقدك أي شيء**.
- ترقية Claude تزيد **حجم الاستخدام (رسائل أطول/أكثر)** وتطيل الجلسة — مفيدة للعمل المكثّف، لكنها **لا تمنع تصفير الحاوية**.
- **توصيتي:** احتفظ دائمًا بآخر ZIP للمصدر (أعطيك إياه)، فهو نسختك الكاملة التي تُعيد البناء منها في أي وقت.

## خارطة الطريق (مراحل، بلا كسر ما يعمل)
- **المرحلة ١ (جاهزة الآن):** مخطّط القاعدة الآمن + المصادقة + الأدوار + RLS + الاشتراكات → ملف `قاعدة-المنصة-متعددة-المدارس.sql`.
- **المرحلة ٢:** ربط التطبيق بـ Auth (تسجيل دخول حقيقي) + كتابة كل عملية مباشرة للجداول (حفظ فوري).
- **المرحلة ٣:** لوحة مدير المدرسة (يرى معلّميه وفصوله وتقاريره) + دور المساعد/الوكيل.
- **المرحلة ٤:** الاشتراكات والتحصيل + لوحة المشرف العام (أنت) لإدارة المدارس.

## ملاحظة مهمة عن «الحفظ الفوري بلا مزامنة»
- يعني: كل ضغطة تُحفظ مباشرة في القاعدة السحابية (يتطلب اتصالًا لحظة الحفظ).
- توصية: نُبقي **ذاكرة محلية احتياطية** تحفظ العملية إن انقطع النت وتُكملها فور عودته — فلا تُفقد أي عملية حتى مع ضعف الشبكة.
